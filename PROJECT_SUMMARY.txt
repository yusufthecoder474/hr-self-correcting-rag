HR SELF-CORRECTING RAG ASSISTANT
================================

PROJECT TITLE
-------------
Enterprise HR Knowledge Assistant
Self-Correcting RAG with Learned Halting


PROJECT OVERVIEW
----------------
A retrieval-augmented HR policy assistant that combines:

1. Semantic retrieval using SentenceTransformers.
2. ChromaDB vector storage.
3. Local retrieval critic.
4. Query rewriting for self-correction.
5. Learned STOP/CONTINUE halting policy.
6. FastAPI backend.
7. Browser-based frontend.
8. Gemini-based final answer generation with local fallback.

LOCAL RETRIEVAL CRITIC
----------------------
The current local critic combines:

- semantic similarity
- keyword overlap

Current combined score:

0.6 * semantic similarity
+
0.4 * keyword overlap

Current decision threshold:

score >= 0.75:
SUFFICIENT

score < 0.75:
INSUFFICIENT

IMPORTANT:
The critic-defined decision is a retrieval-quality proxy.
It is NOT equivalent to independently verified answer-level accuracy.

BASELINE DEFINITION
-------------------
The baseline is an up-to-three-attempt retrieval budget.

The implementation allows fewer than three attempts when the
query rewrite produces no change.

Therefore the baseline is described as:

"3-Attempt Budget"

and not as an unconditional fixed three-iteration execution.

API COST LIMITATION
-------------------
A small Normal-RAG vs Learned-RAG monetary-cost pilot was attempted.

Gemini service availability was unstable and repeatedly returned
503/unavailable responses.

Therefore the pilot did NOT produce sufficiently matched
successful measurements for a defensible monetary-cost comparison.

No monetary API-cost reduction is claimed from the pilot.

The API measurements are retained as instrumentation for future
controlled experiments.

CURRENT RESEARCH CONCLUSION
---------------------------
On the 100-question VIT HR evaluation set, the learned halting
policy reduced average retrieval attempts from:

1.7600
to
1.3500

corresponding to:

23.30%

lower average retrieval attempts.

The same critic-defined retrieval success rate was observed for
both methods:

75.00%

The learned policy also produced lower measured local
retrieval-loop wall-clock time and CPU time.

Observed local-loop reductions:

Wall-clock:
24.12%

CPU time:
23.79%

These results support the observation that the learned halting
policy can reduce retrieval effort under the project's
critic-defined evaluation procedure.

They do NOT constitute independent proof of answer-level accuracy.


IMPORTANT LIMITATIONS
---------------------
1. The main evaluation contains 100 questions.

2. Critic-defined success is a retrieval-quality proxy rather
   than independently verified answer-level accuracy.

3. Full independent human validation has not been completed for
   the complete 100-question set.

4. Some retrieved contexts can contain unrelated neighboring
   policy text due to PDF extraction and chunking behavior.

5. Gemini API instability prevented a defensible matched
   monetary-cost comparison.

6. Local-loop latency excludes final Gemini answer-generation
   latency.

7. The 3-Attempt Budget baseline is an up-to-three-attempt budget
   and can stop earlier if the query rewrite produces no change.

8. A faithful TASR reproduction is not claimed.

9. Additional stopping-method baselines and broader independent
   evaluation would strengthen the research.


TASR NOTE
---------
TASR is treated as related work rather than a reproduced baseline.

The current system uses:

SentenceTransformer retrieval
+
local retrieval critic
+
query rewriting
+
learned Logistic Regression halting

A faithful TASR reproduction is not claimed because the current
implementation does not expose the same calibrated LLM logit-based
signal required by that method.
