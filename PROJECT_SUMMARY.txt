HR SELF-CORRECTING RAG ASSISTANT
================================

PROJECT TITLE
-------------
Enterprise HR Knowledge Assistant
Self-Correcting RAG with Learned Halting


PROJECT OVERVIEW
----------------
A retrieval-augmented HR policy assistant that combines:

1. Semantic retrieval using SentenceTransformers.
2. ChromaDB vector storage.
3. Local retrieval critic.
4. Query rewriting for self-correction.
5. Learned STOP/CONTINUE halting policy.
6. FastAPI backend.
7. Browser-based frontend.
8. Gemini-based final answer generation with local fallback.

API COST LIMITATION
-------------------
A small Normal-RAG vs Learned-RAG API-cost pilot was attempted.

Gemini service availability was unstable and repeatedly returned
503/unavailable responses.

Therefore the pilot did NOT produce sufficiently matched successful
measurements for a defensible monetary-cost comparison.

No API monetary-cost reduction is claimed from the pilot.

The available API measurements are treated as instrumentation and
preliminary evidence only.

CURRENT RESEARCH CONCLUSION
---------------------------
On the 100-question VIT HR evaluation set, the learned halting policy
reduced average retrieval attempts from 1.7600 to 1.3500, corresponding
to a 23.30% reduction in retrieval work.

The same 75.00% critic-defined retrieval success rate was observed for
both Fixed-3 and Learned Halting.

The learned policy also produced lower measured local retrieval-loop
wall-clock and CPU time.

These results demonstrate adaptive retrieval effort reduction while
preserving the same critic-defined retrieval success on this evaluation
set.


IMPORTANT LIMITATIONS
---------------------
1. The evaluation contains 100 questions.
2. Critic-defined success is not independent answer-level accuracy.
3. Independent human validation is not complete for the full
   evaluation set.
4. Some retrieved contexts can contain unrelated neighboring policy
   text because of PDF extraction/chunking behavior.
5. Gemini API availability prevented a valid matched monetary-cost
   comparison.
6. Local-loop latency excludes final Gemini answer-generation latency.
7. A faithful TASR reproduction is not claimed.
8. Additional comparison with other stopping methods and broader
   independent evaluation would strengthen the research.


TASR NOTE
---------
TASR is treated as related work rather than a reproduced baseline.

The current system uses:

SentenceTransformer retrieval
+
local retrieval critic
+
query rewriting
+
learned Logistic Regression halting.

A faithful TASR reproduction is not claimed because the current
implementation does not expose the same calibrated LLM logit-based
signal required by that method.
